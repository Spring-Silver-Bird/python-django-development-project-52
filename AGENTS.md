# AGENTS.md

Django 6.1 task-manager (users / statuses / labels / tasks). Python >=3.12, managed with `uv`. The deployed app and tests are the ground truth; this file lists the non-obvious parts.

## Commands (uv-based, no venv activation needed)

- Install deps: `uv sync --dev` (Makefile `make install`)
- Run tests: `make tests` or `uv run pytest` — 67 tests, ~30s, all in `task_manager/tests/` (the per-app `tests.py` files are empty stubs; do not add tests there)
- Single file: `uv run pytest task_manager/tests/test_tasks.py`
- Migrations: `uv run python manage.py migrate` (`make migrate`)
- Build order matters (see `build.sh`): `make install && make tailwind-build && make collectstatic && make migrate`
- Tailwind: `make tailwind-build` runs `manage.py tailwind build`; it generates gitignored `assets/css/tailwind.css`. Edit `tailwind/tailwind.css`, never the generated CSS.
- No linter/formatter config exists (no ruff/flake8/black in `pyproject.toml`).

## Architecture

- Feature apps (`task_manager.users|statuses|tasks|labels`) each have their own `urls.py` with `app_name` matching the dir; root `task_manager/urls.py` includes them under those namespaces (e.g. `tasks:list`, `users:update`). URL names are asserted in tests.
- Templates are project-level in `task_manager/templates/<app>/...` (shared `base.html`), NOT per-app `templates/`.
- All views are generic CBVs (ListView/CreateView/UpdateView/DeleteView) + `SuccessMessageMixin`; success_url is always `reverse_lazy('<app>:list')`.
- Permission model: everything task/status/label is `LoginRequiredMixin`. Any logged-in user may update a task (`test_update_other_allowed`). Delete is restricted to the author via `UserPassesTestMixin`; `handle_no_permission()` flashes a Russian `messages.error` and redirects to the list. Users can only edit/delete themselves (`test_func` compares pk). User delete is blocked (flash + redirect) if the user has authored/executed tasks; status/label FK deletes fall back on `on_delete=PROTECT` + `ProtectedError` handler.
- Task `author` is set in `form_valid` via `form.instance.author = self.request.user`.
- `Task.name` is unique with custom `clean()` raising `ValidationError`.
- Tests are plain `django.test.TestCase` classes (no pytest fixtures, no conftest). `DJANGO_SETTINGS_MODULE` and pythonpath come from `[tool.pytest.ini_options]` in `pyproject.toml`.

## UI language

- `LANGUAGE_CODE = 'ru'`; all form labels, success/flash messages, and template copy are Russian, and tests assert the exact Russian strings (e.g. `'Задача успешно создана'`, `'Задачу может удалить только ее автор'`). Keep new strings Russian to match.

## Ops / env

- `dj_database_url.config()` in settings: SQLite (`db.sqlite3`) by default, Postgres when `DATABASE_URL` is set (Render). `dj` also offers `conn_max_age`.
- Deployed on Render via `gunicorn task_manager.wsgi` (`make render-start`); build step is `./build.sh`.
- `.github/workflows/hexlet-check.yml` is auto-generated by Hexlet — DO NOT EDIT.
- `.env` (gitignored) holds SENTRY_DSN + dev superuser creds; never commit it. `SECRET_KEY` has a dev fallback default (fine locally, must come from env in prod). Sentry init runs unconditionally with an empty DSN default.
- `tmp_*.py` files at repo root are gitignored debug scratch scripts, not part of the app.
